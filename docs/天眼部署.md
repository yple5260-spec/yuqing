## 数据、Secret 与代理

- 平台注入 `TYAPP_DATABASE_URL`；本地可通过未入 Git 的 `.env` 或 `XIN_ENV_FILE` 指定文件读取。外部连接只用于本次授权维护，生产容器使用平台内部连接，不复制外部地址替代内部地址。
- `XIN_DATA_DIR=/data`，`XIN_REQUIRE_POSTGRES=1`；容器未获得数据库变量会拒绝启动，不静默创建 SQLite。未设置连接的本地开发仍可使用 SQLite。
- `XIN_ENCRYPTION_KEY` 绑定运行时 Secret。**如果随后迁移旧数据，必须使用旧库原密钥**。不能先灌入新业务数据再直接覆盖迁移；目标非空时迁移工具拒绝导入。
- 证据已使用私有S3：完整映射平台注入的六个 `TYAPP_S3_*` 变量，SigV4、Path-style、`us-east-1`。`evidence_objects` 表保存证据ID、Bucket与对象Key，不保存Endpoint或签名链接；现有文件名与业务归属保留在evidence表。密文原样存储，前端仍通过鉴权接口取图，不获得S3凭据。
- `/data` 仍保存文件锁、首次凭据及本地密钥文件（若未使用Secret）；须可写。S3迁移后不再依赖本地media提供业务图片，原目录仅作回退副本，数据库备份不包含S3对象和原密钥。
- `XIN_SECURE_COOKIE=1`。Cookie 名为 `xin_bfzx_yqda_session`，路径根据当前入口收窄，不设父域 Domain。旧版会话需重新登录，密码与角色不变；两个入口的登录会话不保证互通。
- `XIN_ALLOWED_HOSTS` 精确配置实际公开域名，加 `127.0.0.1,localhost` 供健康检查；不要使用通配符。子域名须以实际发布产生的入口为准，不能根据 slug 宣称已开通。
- **`XIN_TRUSTED_PROXY_CIDRS` 需平台管理员确认实际应用代理来源网段**，默认只信任回环地址。不能设置 `0.0.0.0/0`。后端只接受可信代理的 `X-OneView-Route-Base`，值只能为 `/` 或 `/apps/bfzx-yqda`；由它输出页面 `<base>`，资源、API、图片与下载统一跟随。上游已剥离路径前缀，应用不再剥离。
- 代理必须保留公开请求 Host，使 Origin/Host 校验一致；不要通过放宽 CSRF 绕过错误的代理配置。

## 管理员与首次启动

应用首次空库启动会创建本地 admin 和 reviewer，各生成随机密码，写入 `/data/首次登录凭据.txt`。通过平台批准的容器文件/受控运维途径领取，不打印到聊天或日志。admin 负责账号管理，reviewer 独立复核；现有角色约束保持。迁移旧库后沿用原账号密码哈希，不重新分配权限。

若计划导入旧库，优先先停机迁移，再首次启动业务应用。临时预览须使用独立测试 schema/目录，避免把随机初始化账号写入待迁移的正式空库。当前单实例锁会拒绝同数据目录/数据库的第二实例；更新需要确认平台可先停止旧实例再启动新实例，可能有短时中断，不宣称支持无停机滚动更新。

## 旧 SQLite 迁移

1. 停止原应用与目标应用，取得完整源目录：`xin.db`、原 `encryption.key`、`media/`。原密钥若在环境变量托管，安全设置同一个 `XIN_ENCRYPTION_KEY`；不要求把密钥发到聊天。
2. 配置目标 PostgreSQL 连接与独立目标 `XIN_DATA_DIR`，目标文件目录不能是源目录；确认目标应用表均无数据。不要提前让正式应用初始化账号。
3. 默认只预检：`python migrate_sqlite.py <源data目录>`。检查 SQLite 完整性、所有加密业务体可解密、导出和证据 SHA-256、审计链、目标空库。
4. 正式导入：`python migrate_sqlite.py <源data目录> --apply`。先在目标目录保存 `pre-migration-backup`（一致性SQLite副本、原密钥、media），再建表、同事务导入账号/规则/档案/历史/证据元数据/复核/覆盖/审计/导出/导入。逐表核对条数和内容，恢复自增序列；Session 和登录失败计数不迁移，所有用户重新登录。
5. 密文保持原样，图片仍为加密文件；源数据库只读，不删除。随后按下方S3流程迁移目标media，平台Secret使用同一个原密钥，再启动并核对实际登录、证据、当前复核和导出。

预检不建表、不初始化账号。正式迁移失败时 PostgreSQL 导入事务回滚，备份及可能已复制的附件会保留，不能靠删源目录处理；先检查错误与目标状态，重试前人工保留或移走本次备份。备份本身含原密钥，应在受控加密介质保存。本次真实迁移已完成，详见下方记录；不要对已迁入业务数据的目标再次执行导入。

## 备份与回退

`manage.py backup` 仍只适用于 SQLite，连接 PostgreSQL 时会明确拒绝。平台 PostgreSQL 使用受控 `pg_dump`（建议custom格式）与恢复演练，凭据通过安全环境/凭据文件传递，不放命令参数或文档；同时备份S3中被evidence_objects引用的加密对象、尚未迁移的本地media与原加密密钥。S3服务本身不等于已有异机备份。为确保数据库/文件一致性，停业务写入后再做组合备份。

应用镜像回退不回退数据库。原 SQLite 保留用于迁移后业务核对；迁移后 PostgreSQL 已有新增记录时，不能直接切回旧SQLite而丢掉新数据。
