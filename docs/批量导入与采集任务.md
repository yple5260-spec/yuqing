# 批量导入与采集任务

## 使用方式

在“用户档案 → 导入”或“采集任务 → 批量建档”中，下载三项模板，填写“舆情原文链接、手机号、用户姓名”。支持 UTF-8 CSV、XLSX 首个工作表，也可直接粘贴 CSV 文本；每批最多 3000 行。XLSX 手机号建议使用文本格式。

先预览有效行、重复行及错误原因。预览不创建档案或任务；确认后，仅有效行建档、加入采集队列。预览后若其它人抢先创建同一链接，提交时跳过该行，其余有效行继续提交。同一微博的域名或分享形式别名按微博 ID 去重。原有详细字段导入格式保留在格式选项中。

“单条建档”和已有档案的“采集原文与快照”使用相同队列。任务保存后可关闭浏览器；采集依赖业务服务和本地采集环境持续运行。

## 任务与进度

任务页支持批次、状态筛选，每页 100 条，每 5 秒读取一次服务端进度。进度表示该批次已结束条数；无法取得页面内部精确进度时不显示虚构百分比。

| 状态 | 含义 |
| --- | --- |
| 排队中 | 已保存，等待后台执行 |
| 采集中 | 正在访问原文、提取字段并截图 |
| 已完成 | 当前平台支持的原文字段和截图已保存；不表示身份、评分均已完成 |
| 部分完成 | 已保存可取得的字段和截图，仍有字段待核实，例如未登录微博的近 7 天频次 |
| 访问受限 | 遇到验证码或访问限制；不把验证页保存为证据 |
| 失败 | 链接不支持、请求/存储异常、账号权限撤回或档案版本已变化等，页面展示原因 |

管理员和录入员可重新采集已结束的受支持链接任务。重试沿用任务及档案，更新执行次数，不重复建档；不支持的链接需先修改为支持的原文链接。受限或失败任务不自动反复重试。

## 保存与恢复

复用业务数据库，新增 collection_jobs 表，无额外队列服务或依赖。后台按队列顺序逐条执行，不进行并发抓取。业务进程启动时，将上次中断的“采集中”任务恢复为排队；原档案版本仍需匹配。既有实例锁限制同一数据库只运行一个业务服务。

发起账号在执行前、入库前均须仍有采集权限。采集期间的人工修改不会被覆盖。截图证据、档案新版本和任务最终状态在同一数据库事务提交；存储失败则回滚数据库修改。底层对象存储与数据库没有跨服务事务，进程恰好在上传后、数据库提交前中断可能留下未引用对象，不能将其视为已入库证据。

任务状态、批次、次数和时间用于检索；任务结果明细按现有业务密钥加密，审计记录任务创建、开始、结束、恢复与重试。SQLite 迁移脚本兼容旧库，并在源库含 collection_jobs 时迁移、解密校验和比对任务数据。服务初始化负责创建该表，不修改既有档案内容。

## 检查范围

```powershell
.venv/Scripts/python.exe -m unittest discover -s tests -p test_jobs.py -v
.venv/Scripts/python.exe -m unittest discover -s tests -p test_jobs_restart.py -v
.venv/Scripts/python.exe -m unittest discover -s tests -p test_collection.py -v
```

检查三字段 CSV/XLSX、混合批次、链接去重、提交竞态、权限与 CSRF、受限重试、并发编辑保护、存储失败回滚。重启测试启动真实独立服务进程，任务执行中终止进程，再启动同一数据目录，检查恢复后仅有一份档案和证据。自动化业务检查使用隔离 SQLite；PostgreSQL 迁移需另有隔离连接才可验收。

2026-11-15 已在临时隔离业务库完成真实浏览器验收：6 行导入识别出 4 条有效、1 条重复、1 条错误；关闭页面后，真实采集进程分别得到完成、部分完成、访问受限和失败各 1 条。状态筛选、微博采集详情、受限任务重试不重复建档、单条建档跳转任务页均通过，桌面 1440px 和手机 390px 无页面脚本报错。截图及结果保存在本机忽略目录 runtime/jobs-ui/；未向平台 PostgreSQL 或 S3 写入测试数据。本地预览服务重启前已备份 SQLite，原有 14 份档案和 13 份证据保留，新增任务列表初始为空。
