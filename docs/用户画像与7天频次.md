# 用户画像与近7天发布频次

## 档案展示

档案详情新增“用户画像 · 公开账号观察”。录入姓名、手机号和身份核验仍在“身份与域内标签”中，公开账号观察不自动建立自然人绑定，也不按昵称跨账号、跨事件合并。

画像集中展示作者昵称、平台账号 ID、公开精确粉丝数、平台认证状态、原文发布时间；微博另展示原文累计转发、评论、点赞。每项显示字段来源入口、观测时间或缺失原因。已知的粉丝数 0 和“未认证”属于有效观察；未取得的数量保留未知。发布时间只有月日时分时不推测年份，日期精度及时区按原文标注。

原文摘要及字段摘录 SHA-256 放在可展开区域，截图继续进入原有证据库。字段摘要只核对摘录内容，不代表整份 HTTP 响应摘要。时间按浏览器本地时区显示；发布原文中的时间精度和时区另行标注。

## 近7天口径

以本次原文采集时间为结束点，向前 7×24 小时为开始点，使用 `[开始, 结束)` 半开窗口，按 UTC 比较时间。统计同一平台账号的全部公开发布内容，不限于本事件；不以本系统纳库量或账号累计历史发布量代替。发布列表应包含该账号的原创、转发发布；评论和点赞行为不作为发布内容计数。

只有下列条件均满足才计算：账号 ID 明确并与列表一致、来源可追溯、列表窗口与本次采集窗口一致、所有记录具有唯一内容 ID 和含时区的完整发布时间、采集器已确认列表覆盖完整。

- 按内容 ID 去重，窗口外的旧内容不计入，同 ID 的冲突时间视为异常。
- 发布总数为窗口内去重内容数，日均频次为总数 ÷ 7，后台不提前舍入；页面最多显示两位小数。
- 完整空列表得到数量 0、日均 0；没有列表不等于空列表。
- 列表未采全时仅说明已取得的去重样本数，数量和日均仍为未知。
- 作者不一致、范围错误、无时区、未来发布时间或窗口不一致等情形显示“数据待核查”，不计算结果。

当前问政详情页没有唯一作者账号及完整列表；未登录微博尚无可用的完整近7天列表。两类采集均明确记录数据不足原因。本次没有新增登录态或发布列表采集通道，不能将计算器和展示完成理解为已取得真实账号的7天总量。

## 后台数据与兼容

复用加密档案中的 collection 记录，无新增表或依赖。采集器内部的 `account_posts7` 输入包含 `uid`、`scope=account_all`、`source_url`、`window_start`、`window_end`、`complete` 及 `posts`。每条发布记录为 `id`、`uid`、`published_at`。`complete` 必须为布尔值 true，代表采集器已验证窗口与分页完整，不由前端提交。

服务端 portrait.activity7 校验后，将结果保存为 collection.activity7，同时写入 collection.posts7、collection.posts_per_day7。它们表示公开账号观察，不是现有 metrics.posts7 评分项。单条资料表单不能修改采集结果或计算结果。

详情 API 返回统一的 portrait 字段；既有采集记录按原始观测时间生成同样的展示，不要求批量重写历史记录。来源链接改变时，旧采集字段不再显示为当前画像，提示重新采集；历史快照和采集记录保留。同一微博的分享链接别名按微博 ID 比较来源。

现有评分中的“近7天相关去重发布数”和“近30天已核实原创内容数”、阈值、人工指标和规则历史保持原样；公开粉丝数及频次没有自动进入评分。后续若以“条/天”替换评分项，需要另行定义阈值和历史规则兼容。
