# 采集代理配置与验证

2026-11-19，本地独立采集进程已支持从 `.env` 选择代理。默认直连；配置错误或代理失败时不会自动换线路，也不会回退直连。一次页面采集包含原文、图片、脚本和作者资料等多个请求，巨量按请求计费，一条档案不等于一次计费请求。

## 配置

使用现有 `.env` 字段，无需把密码写进代码。选择后重启业务服务：

```dotenv
# direct / juliang / openwrt / custom，默认 direct
XIN_CRAWLER_PROXY=direct
```

| 选择 | 读取的字段 | 行为 |
| --- | --- | --- |
| `direct` | 无 | 直连，不使用两套代理凭据 |
| `juliang` | `juliang_proxy_host`、`juliang_proxy_port`、`juliang_proxy_user`、`juliang_proxy_pass` | 固定隧道入口，出口由供应商轮换 |
| `openwrt` | 优先 `op_proxy_url_http`，否则 `op_proxy_url_socks5` | 从完整 URL 解析地址及认证信息 |
| `custom` | `XIN_CRAWLER_PROXY_SERVER`、`XIN_CRAWLER_PROXY_USERNAME`、`XIN_CRAWLER_PROXY_PASSWORD` | 显式配置其它入口 |

Chromium 支持 HTTP 代理认证，但不支持带账号密码的 SOCKS5 代理；这种配置会直接报告原因。无认证 SOCKS5 可配置，`socks5h` 规范为 Chromium 的 `socks5`。本次未增加 SOCKS 到 HTTP 的中转服务。

当前 `.env` 中有重复的 `op_proxy_port` 键，后一项不是数字。本实现使用完整代理 URL，不读取这些分散的 OpenWrt 字段；取消白名单后的复测已成功，未修改这些旧字段。

只有选中的代理配置通过环境变量传入采集子进程，不放入命令行参数；子进程仍不读取 `.env`，不携带数据库、S3或模型凭据。不关闭 TLS 证书验证，不保存登录态，不自动重试受限页面。

本机隔离预览启动器只读取代理字段，继续使用原隔离 SQLite 和本地附件，不加载平台数据库或 S3 配置。常规业务启动由现有配置加载流程读取 `.env`。

三个新渠道验收完成后，本机`.env`已选择`XIN_CRAWLER_PROXY=openwrt`，服务使用OpenWrt HTTP入口；示例配置及无配置环境仍默认直连。巨量保留为手动可选线路，不自动切换。

## 实测结果

| 检查 | 结果 |
| --- | --- |
| 巨量出口 | 连续三个独立 HTTP 请求均成功，观察到三个不同出口 IP；不推断浏览器复用连接时每个子请求的出口 |
| 巨量浏览器 | HTTP、HTTPS 测试页面均返回200，未关闭证书校验 |
| OpenWrt HTTP | 取消白名单后复测：curl访问HTTP、HTTPS均返回200；Chromium浏览器访问HTTP、HTTPS也均返回200 |
| OpenWrt SOCKS5 | 取消白名单后复测：curl经认证型SOCKS5访问HTTP、HTTPS均返回200；Chromium仍不支持该认证方式，业务采集使用HTTP入口 |
| 现有红网采集链路 | 通过巨量取得正文和可解码截图，未写入业务库 |
| 现有微博采集链路 | 本次通过巨量采集失败，不能认定已稳定可用 |
| OpenWrt真实采集链路 | 红网、微博均取得正文、采集时间和可解码截图；微博粉丝数未取得；未写入业务库 |

首次测试时OpenWrt返回空响应或关闭SOCKS协商；用户取消白名单后，同一配置复测通过。OpenWrt四次HTTP/HTTPS请求的IP回显出现三个不同地址，尚未验证固定出口或会话稳定性。巨量命令行 curl 的 HTTPS 测试出现过连接或证书错误；上表的巨量浏览器 HTTPS 成功以 Chromium 实测为准。
